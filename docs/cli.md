# Command-line interface

Install `protein-fasta[cli]`. Every command is a short single word, parameters are generated by
Cyclopts, and progress/reporting goes through Loguru.

## FASTA inspection

```bash
protein-fasta table database.fasta proteins.csv
protein-fasta table database.fasta proteins-with-hashes.csv --checksums
protein-fasta table database.fasta strict.csv --strict
protein-fasta basic database.fasta proteins.xlsx --no-sequence
protein-fasta configured database.fasta proteins.parquet \
  --rules uniprotkb.json --rules refseq.json --classifiers classifiers.json
protein-fasta formats database.fasta formats.csv
protein-fasta diagnostics database.fasta
```

The diagnostics report includes sequence counts, residue totals, length quartiles, amino-acid
counts and percentages, identifier namespaces, overlapping classifications, normalization changes,
and illegal sequence characters.

`table` and `configured` parse every row accepted by exactly one available rule; unmatched or
ambiguous rows remain with null enrichment fields. `--strict` instead requires one rule to accept
the complete file and otherwise returns only `id`, `description`, and `sequence`. `basic` always
guarantees that base schema, while `formats` exports parser-recognition evidence. CSV, TSV, XLSX,
and Parquet are selected by output suffix. `--no-sequence` applies to protein-row exports.
`table --checksums` adds a hexadecimal BLAKE2b-128 `sequence_hash` over the normalized sequence and
a versioned `id_sequence_fingerprint` for each row.

## Digestion and checksums

```bash
protein-fasta digest database.fasta peptides.parquet
protein-fasta digest database.fasta peptides.tsv --config digestion.json
protein-fasta checksum database.fasta
```

`digest` exports `protein_id`, `peptide`, and `missed_cleavages`. `checksum` reports exact-file
`md5-file-v1` and normalized ID/sequence-content `blake2b-128-id-sequence-pairs-v1`; the labels are
part of the result and prevent algorithm ambiguity.

## Database construction

```bash
protein-fasta build build.json
```

The JSON is the whole request, so reproducibility does not depend on remembering many switches.
Relative paths resolve beside the JSON document. The command writes the FASTA and a
`.fasta.manifest.json` sidecar with the effective request, package version, MD5 checksums for every
input and the output, counts, normalization changes, and generation evidence.

A minimal request is:

```json
{
  "schema_version": "0.1",
  "targets": ["human.fasta"],
  "output_dir": "build",
  "date": "2026-08-27",
  "name_fields": {
    "project": 42261,
    "dbn": 1,
    "description": "human"
  },
  "add_decoys": true,
  "decoy": {
    "mode": "reverse"
  }
}
```

The document can additionally embed naming/metadata rules, named contaminant blocks, an explicit
registry-diagnostic document, shuffled or DecoyPYrat settings, and shuffled or foreign-species
entrapment settings.

## Registry indexing and analytics

```bash
# SQLite is selected by the suffix and default document
protein-fasta index databases registry.sqlite3 --recursive

# DuckDB selection is explicit in JSON and agrees with the suffix
protein-fasta index databases registry.duckdb --config registry.json

protein-fasta registry registry.sqlite3 databases.csv
protein-fasta compare registry.sqlite3 12 comparison.xlsx --kind target
protein-fasta pairs registry.sqlite3 pairs.tsv --ids ids.tsv --sequences sequences.tsv
protein-fasta cluster registry.sqlite3 clusters.csv --metric target_sequences
```

`registry` exports database summaries and fingerprints. `compare` exports the selected database's
directional coverage, containment, Jaccard, exact-pair, changed-ID, and relationship evidence.
`pairs` exports all materialized target/contaminant pair metrics and optional symmetric target-ID
or target-sequence matrices. `cluster` exports deterministic average-linkage merge rows and logs
the leaf order.

Registry policy is also a Pydantic JSON document:

```json
{
  "schema_version": "0.1",
  "registry": {
    "backend": "duckdb"
  },
  "max_fasta_file_size_gib": 5.0,
  "max_detailed_entries": 200000,
  "metadata_aa_sample_size": 20000,
  "overlap_threshold": 0.99
}
```

Source and registry paths are command arguments because they identify a run; the JSON stores the
portable policy. Run `protein-fasta --help` or `<command> --help` for the generated reference.
